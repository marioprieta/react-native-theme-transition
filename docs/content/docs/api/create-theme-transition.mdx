---
title: createThemeTransition
description: Factory function that creates a typed theme transition system from your theme definitions.
---

Validates configuration at initialization and returns a self-contained
`{ ThemeTransitionProvider, useTheme }` API. No singletons — multiple
theme scopes can coexist.

TypeScript infers theme names and color tokens from the `themes` object.
No manual generics needed.

```ts
const { ThemeTransitionProvider, useTheme } =
  createThemeTransition({
    themes: { light, dark },
    duration: 350,
    onTransitionStart: (name) => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium),
    onThemeChange: (name) => analytics.track('theme_switch', { theme: name }),
  });
```

## Config

| Option | Type | Default | Description |
|---|---|---|---|
| `themes` | `Record<string, ThemeDefinition>` | *required* | Object of theme definitions. All themes must share the same color token keys. The name `'system'` is reserved. |
| `animated` | `boolean` | `true` | Global default for animated switches. When `false`, every `setTheme` / `select` call switches instantly unless the caller opts in with `{ animated: true }`. |
| `duration` | `number` | per-kind default | Default transition duration in ms. Per-kind defaults when omitted: 350ms for fade / reveal / strip, 800ms for shape (`heart`, `star`), 750ms for shader (`pixelize`, `dissolve`). |
| `transition` | `TransitionType` | `'fade'` | Default transition style used when `setTheme` is called without a `transition` option. |
| `reduceMotion` | `boolean` | `true` | Honor the OS "Reduce Motion" accessibility setting by falling back to an instant switch. Read the current value via the exported `useReducedMotion()` hook. |
| `backgroundColor` | `(colors) => string` | first token | Picks the color painted behind the children tree as a fallback for any transparent region the Skia snapshot path can leave (e.g. the area below a scrolled `ScrollView` on Android). Defaults to the first token in the current theme. [See below.](#backgroundcolor) |
| `systemThemeMap` | `{ light: Name, dark: Name }` | — | Maps OS appearance to theme names. Required when your themes are not named `'light'`/`'dark'` and you want system mode. |
| `darkThemes` | `ThemeName[]` | `[systemThemeMap.dark]` or `['dark']` | Theme names that use a dark color scheme. Every entry must match a key in `themes`. The library calls `Appearance.setColorScheme` internally to keep native UI (alerts, date pickers) in sync. |
| `onTransitionStart` | `(name: Name) => void` | — | Called when an animated transition begins, before screenshot capture. Does not fire for instant switches. |
| `onTransitionEnd` | `(name: Name) => void` | — | Called after an animated transition completes. Does not fire for instant switches or capture failures. |
| `onThemeChange` | `(name: Name) => void` | — | Called on every theme change — animated, instant, or system-driven. The only callback guaranteed to fire. |

### Theme definitions

Every theme must share the exact same token keys. Mismatched keys throw at initialization.

```ts
const light = { bg: '#fff', text: '#000', primary: '#007AFF' };

// Type-safe enforcement of matching keys on secondary themes:
const dark: Record<keyof typeof light, string> = {
  bg: '#000', text: '#fff', primary: '#0A84FF',
};
```

Rules:
- At least one theme required
- `'system'` is reserved — cannot be a theme key
- Keys must be identical across all themes (order doesn't matter)

### System theme mapping

Maps OS appearance (`'light'` / `'dark'`) to your theme names. Required when themes
aren't named `'light'`/`'dark'` and you want system mode.

```ts
createThemeTransition({
  themes: { sunrise, midnight, ocean },
  systemThemeMap: { light: 'sunrise', dark: 'midnight' },
});
```

Both `light` and `dark` must be provided. Values must reference existing theme names.

### Dark themes

The library automatically calls `Appearance.setColorScheme` to keep native UI
elements (alerts, date pickers, keyboards) in sync. `darkThemes` tells it which
themes use a dark color scheme.

```ts
createThemeTransition({
  themes: { light, dark, ocean, rose },
  darkThemes: ['dark', 'ocean'],
  systemThemeMap: { light: 'light', dark: 'dark' },
});
```

Defaults to `[systemThemeMap.dark]` if `systemThemeMap` is provided, otherwise `['dark']`.
In system mode the library sets `Appearance.setColorScheme('unspecified')` so the OS
drives native appearance.

### backgroundColor

Getter that picks the "root background" color from the current theme. The library
paints this color behind your tree so any transparent regions produced while the
Skia snapshot is rendered fall back to the theme's background instead of the
Activity's default window color (which is typically white on Android).

```ts
createThemeTransition({
  themes: { light: { bg: '#fff', text: '#111' }, dark: { bg: '#000', text: '#fff' } },
  backgroundColor: (colors) => colors.bg,
});
```

If you omit it, the library uses the first token in the current theme.

> **ScrollView gotcha (Android):** don't put `backgroundColor` on a root
> `ScrollView`'s `style` — Android's native drawing cache keeps off-screen
> regions on the previous theme's color after a swap. Put it on
> `contentContainerStyle` instead, or rely on this config option and leave the
> ScrollView transparent. See [Troubleshooting](/docs/guides/troubleshooting).

## Type inference

You never need to pass generic types manually. See the full
[type inference example](/docs/types#type-inference-example) for how theme
names and token keys flow into `useTheme` automatically.

## Validation errors

`createThemeTransition` throws at initialization when config is invalid. Most common cases:

- Empty `themes`
- `'system'` used as a theme key
- Theme token keys do not match across themes
- Invalid `duration` (must be finite and non-negative)
- Invalid `transition` value
- `systemThemeMap` missing `light`/`dark` or pointing to unknown themes
