title: useTheme
description: Hook returning the current theme state, transition controls, and selection tracking.

Returns the current theme state, transition controls, and selection tracking in
a single object. Throws if called outside a `ThemeTransitionProvider`.

## Basic usage

```ts
const { colors, name, setTheme, isTransitioning, selected, select } = useTheme();
```

| Property | Type | Description |
|---|---|---|
| `colors` | `{ [token]: string }` | Current theme's color values, fully typed to your token names. |
| `name` | `ThemeName` | Active theme name (resolved, never `'system'`). |
| `setTheme` | `(name \| 'system', opts?) => boolean` | Trigger a theme change. Returns `true` if state changed, `false` if no-op. |
| `isTransitioning` | `boolean` | `true` while a transition overlay is visible. |
| `selected` | `ThemeName \| 'system'` | Currently selected option (for picker UIs). |
| `select` | `(option, opts?) => void` | Select a theme with transition-safe timing. |

### Color tokens

Fully typed to your token names. TypeScript provides autocomplete:

```ts
colors.background  // autocomplete works
colors.foo         // TypeScript error
```

### Active theme name

Always the resolved theme name, never `'system'`. Even in system mode, `name` returns
the actual theme (`'light'` or `'dark'`, or whatever `systemThemeMap` resolves to).

### Transition state

`true` from after the screenshot is captured until the transition animation completes. Touch input
is blocked immediately when `setTheme` is called, regardless of this flag.
Use it to:
- Disable toggle buttons (`disabled={isTransitioning}`)
- Defer expensive renders
- Show loading indicators

<Callout type="info">
  Touch blocking starts immediately when `setTheme()` is called (synchronous, via
  Reanimated shared value). `isTransitioning` becomes `true` later, after the screenshot
  is captured. Use `disabled={isTransitioning}` on buttons as a convenience — the library
  already blocks touch input internally from the moment `setTheme()` is called.
</Callout>

## Changing themes

| Param | Type | Description |
|---|---|---|
| `name` | `ThemeName \| 'system'` | Target theme or system mode |
| `options` | `SetThemeOptions` | Optional transition configuration |

### Transition options

`SetThemeOptions` is a discriminated union: the `transition` field selects a
variant and the valid extra fields depend on it. See
[`SetThemeOptions`](/docs/types#setthemeoptions) for the full table.

**Common fields (every variant):**

| Option | Default | Description |
|---|---|---|
| `animated` | `config.animated ?? true` | `false` for instant switch, no screenshot or animation |
| `duration` | `config.duration` (or per-kind default) | Override transition duration in ms |
| `easing` | `Easing.out(Easing.cubic)` | Any Reanimated `EasingFunction` |
| `onTransitionStart` | — | Per-call start callback (fires after config-level) |
| `onTransitionEnd` | — | Per-call end callback (fires after config-level) |

**Per-transition extras:** `origin` + `inverted` for reveals, `direction` for
wipe/slide, `axis` for split, `blockSize` for pixelize, `grainSize` for
dissolve. TypeScript rejects invalid combinations at compile time.

```ts
// Default fade
setTheme('dark');

// Circular reveal from a pressed button with haptic feedback
setTheme('dark', {
  transition: 'circularReveal',
  origin: buttonRef,
  onTransitionStart: () => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium),
});

// Wipe to the right, 500ms
setTheme('dark', { transition: 'wipe', direction: 'right', duration: 500 });

// Inverted heart — old theme shrinks into a heart
setTheme('dark', { transition: 'heart', origin: ref, inverted: true });
```

### Behavior rules

1. **Same theme and same mode** — returns `false` (no-op)
2. **During transition** — returns `false` (rapid-press guard, no queue). Wait
   for `isTransitioning` to become `false` before retrying — bind the retry
   to a `useEffect` watching the flag rather than polling.
3. **`'system'`** — enters system-following mode, subscribes to OS changes
4. **Explicit name** — exits system-following mode
5. **`animated: false`** (or config-level) — instant switch, only `onThemeChange` fires
6. **Capture failure** — falls back to instant switch, `onTransitionEnd` skipped

## Selection tracking

`selected` and `select` come back from every `useTheme()` call — you don't need to
opt in. Use them whenever your UI has a visual indicator that follows the chosen
theme (highlighted button, toggle thumb, checkmark).

### When to use `setTheme` vs `select`

| Use... | When |
|---|---|
| `setTheme(name, opts)` | Programmatic changes, non-UI triggers, or when you don't care about a "pressed" highlight |
| `select(option, opts)` | User-driven picker UIs where a press highlight needs to animate with the transition |

`select` defers `setTheme` by one animation frame so the pressed state paints
before the screenshot is captured — the highlight ends up frozen in the overlay
and travels with the animation instead of popping in mid-transition.

### `initialSelection` override

```ts
const { selected, select } = useTheme({ initialSelection: 'system' });
```

| Option | Type | Default | Description |
|---|---|---|---|
| `initialSelection` | `ThemeName \| 'system'` | current theme name | Starting value for `selected` (read once, like `useState`) |

By default, `selected` is seeded with the current theme name. Pass
`initialSelection` only when you want it to start as `'system'` or a value that
differs from `name` (e.g. hydrating from a persisted store).

### Transition-safe timing

On iOS 120Hz displays, calling `setSelected()` and `setTheme()` in the same event
handler doesn't give React enough time to paint the selection before the library
captures the screenshot. `select` solves this by:

1. Updating the selection state immediately
2. Deferring `setTheme` by one `requestAnimationFrame`
3. Using an internal press lock ref to prevent rapid presses during transitions

If `select()` is called during a transition, it's silently ignored (returns without action).
Add `disabled={isTransitioning}` to your Pressable for visual feedback — but even without it,
the internal lock prevents race conditions.

### Local state caveat

`selected` is managed locally inside the hook. If the theme changes externally — via a
system appearance change — the context `name` updates but `selected` does not. Use `name`
for display and `selected` only for the highlight state.

### With external stores

When persisting to Zustand, Redux, or MMKV, call `select()` and the store setter together
in `onPress`. Don't use a reactive bridge that calls `setTheme` on every store change —
it races with `select()`'s deferred timing and reverts the pill.

```tsx
onPress={() => {
  select(mode);       // visual transition
  setColorMode(mode); // persistence
}}
```

See [State Managers](/docs/recipes/zustand) for the full pattern including hydration.
