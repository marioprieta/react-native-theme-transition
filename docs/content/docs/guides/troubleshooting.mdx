## iOS picker flickering

**Symptom:** On iOS, a theme picker with highlighted buttons flickers during the
cross-fade — the selection indicator alternates between old and new positions.

**Cause:** Calling `setSelected()` and `setTheme()` in the same event handler doesn't
give React enough time to paint the selection before the screenshot captures.

**Fix:** Use `select()` instead of calling `setSelected()` + `setTheme()` directly:

```tsx
const { selected, select, colors, isTransitioning } = useTheme();

<Pressable onPress={() => select(option)} disabled={isTransitioning}>
```

`select()` and `setTheme()` come back from every `useTheme()` call — no options form
required. Pass `{ initialSelection: 'system' }` only if you want the initial
`selected` to start as `'system'` instead of the current theme name.

See [Theme Picker example](/docs/examples/theme-picker) for the complete pattern.

## Picker pill flashes back after tapping

**Symptom:** Tapping a theme option briefly highlights it, then the pill snaps
back to the previous selection. The theme changes but the picker is wrong.

**Cause:** A reactive bridge (`useEffect → setTheme`) fires before `select()`'s
deferred `requestAnimationFrame`. The bridge steals the transition, and when
`select()`'s `setTheme` runs, `transitioningRef` is `true` → returns `false` →
`select()` reverts the pill.

**Fix:** Use a **hydration-only bridge** that syncs once on app start, then let
the picker call `select()` + store setter directly in `onPress`:

```tsx
onPress={() => {
  select(mode);       // visual transition
  setColorMode(mode); // persistence
}}
```

See [State Managers](/docs/recipes/zustand) for the full pattern.

## Native Switch flickers

**Symptom:** On iOS, a native `<Switch>` thumb appears mid-slide in the screenshot.

**Cause:** iOS's UISwitch runs a ~250ms Core Animation with no completion callback.
The Skia snapshot captures the on-screen visual state — including the thumb mid-slide.

**Fix:** Use a [custom toggle](/docs/examples/theme-toggle) built with `select()`
and plain React styles (no Reanimated).

## Overlay stays visible / app seems frozen

**Symptom:** The screen appears frozen — touches don't work.

**Check:**
- Look for `[react-native-theme-transition] Failed to capture screenshot` in the console
- Verify `@shopify/react-native-skia` is properly installed (`npx expo doctor`)
- Ensure the root `View` has `collapsable={false}` (set internally)

## Flash on theme change (no animation)

**Causes:**

1. **`animated: false`** — Check if you're passing `{ animated: false }` in options, or if config-level `animated: false` is set
2. **Reduce Motion enabled** — iOS Settings → Accessibility → Motion → Reduce Motion. The library honors it by default. Set `reduceMotion: false` in config to opt out
3. **Provider placement** — `ThemeTransitionProvider` must wrap the full visible tree
4. **`@shopify/react-native-skia` not installed** — screenshot capture throws, falls back to instant switch
5. **Missing worklets plugin** — `react-native-worklets/plugin` must be the last plugin in `babel.config.js`

**Fix:** Verify provider placement, peer dependencies, and babel config. Restart with `npx expo start -c`.

## Reveal starts from the wrong place

**Symptom:** `circularReveal` (or `heart` / `star`) animates from the center
of the screen instead of where the user tapped.

**Causes:**

1. **Ref unmounted** — the view the `origin` ref points to was unmounted between
   the tap and the capture (e.g. it lives inside a `Modal` that closes during
   the transition). Use an explicit `{ x, y }` point instead, or make sure the
   ref's host view stays mounted until the transition ends.
2. **Ref points outside the provider** — only views rendered inside
   `ThemeTransitionProvider` are measured correctly. Views in portals / modals
   at the root may fall outside.
3. **Measurement failed silently** — if `measure()` returns no coordinates,
   the library falls back to the center of the screen.

## My transition picker is missing the new types

**Symptom:** Your own transition picker UI hardcodes the list and is missing
`heart`, `star`, `pixelize`, `dissolve`, or new variants added later.

**Fix:** Import the canonical list instead of hardcoding it:

```ts
import { TRANSITION_TYPES } from 'react-native-theme-transition';

{TRANSITION_TYPES.map((t) => (
  <Pressable key={t} onPress={() => setTheme('dark', { transition: t })}>
    <Text>{t}</Text>
  </Pressable>
))}
```

## Duplicate plugin/preset detected

**Symptom:** `SyntaxError: Duplicate plugin/preset detected.`

**Cause:** From **Expo SDK 55**, `babel-preset-expo` already includes `react-native-reanimated/plugin`.

**Fix:** On SDK 55+, remove `'react-native-reanimated/plugin'` from your plugins:

```js
plugins: [
  // SDK 55+: babel-preset-expo already includes reanimated/plugin
  'react-native-worklets/plugin', // must be last
],
```

## Cannot find module 'babel-preset-expo'

**Cause:** Expo SDK 55 blank templates no longer include `babel-preset-expo` as a dependency.

**Fix:**

```bash
npx expo install babel-preset-expo
```

## System theme not following OS

**Causes:**

1. **System mode not activated** — Verify `initialTheme="system"` or `setTheme('system')`
2. **Manual setTheme overrides** — `setTheme('dark')` exits system mode
3. **Missing `systemThemeMap`** — Required for custom theme names
4. **iOS Simulator** — Use `Cmd+Shift+A` to toggle appearance

---

## Type errors on colors

**Symptom:** `Property 'myToken' does not exist on type '{ ... }'`

**Fix:** Ensure all themes share identical keys:

```ts
const light = { bg: '#fff', text: '#000' };
const dark: Record<keyof typeof light, string> = { bg: '#000', text: '#fff' };
```

---

## Theme changes but no animation plays

**Causes:**

1. **`duration: 0`** — Set a positive duration
2. **`animated: false`** — Check all `setTheme` call sites
3. **System-driven in background** — Background changes use instant switch by design
4. **Bridge firing on mount** — Normal behavior for first load

---

## setTheme does nothing

**Causes:**

1. **Same theme** — `setTheme('dark')` when already dark returns `false`
2. **During transition** — Returns `false`, system mode is **not** activated. Retry after `isTransitioning` becomes `false`
3. **System mode dedup** — `setTheme('system')` when OS-resolved matches current activates system mode but no visual change

---

## Double transition on app start

**Cause:** `initialTheme` resolves to one theme, then a bridge fires `setTheme` with a different stored preference.

**Fix:** Pass the stored preference as `initialTheme`:

```tsx
import { useThemeStore } from '@/stores/theme-store';

const colorMode = useThemeStore((s) => s.colorMode);
<ThemeTransitionProvider initialTheme={colorMode}>
```

## Android: capture returns blank

**Causes:**

1. **`collapsable` not set** — The root View needs `collapsable={false}` (set internally)
2. **Hardware acceleration issues** — The library falls back to instant switch automatically
3. **View not fully rendered** — The library waits frames before capture to prevent this

---

## Fast Refresh issues

**Symptom:** After saving a file during development, the overlay stays visible or
system mode stops following the OS.

**Cause:** Fast Refresh reloads JS but does not reset native state.
`Appearance.setColorScheme` from the previous session persists, and if a transition
was in progress, the overlay cleanup may not fire.

**Fix:** Perform a full reload (`Cmd+R` / `R R`). This only affects development.

## Android: light-colored strip shows behind content on theme change

**Symptom:** On Android, when you change the theme, a region of the screen — usually
content that lives below the initial fold of a root `ScrollView` — briefly flashes
the *initial* theme's background color (e.g. a light `#F5F5F7` showing through
during a `dark → ocean` transition). iOS is fine.

**Cause:** Native Android `ScrollView` caches its `backgroundColor` in the view's
drawing cache. When you set `backgroundColor` directly on the `ScrollView`'s
`style` prop, Android only invalidates the visible rect on theme changes —
off-screen content (anything below the fold) keeps the cached color until the
user scrolls and forces a full redraw.

**Fix:** Don't put `backgroundColor` on the `ScrollView` itself. Move it to
`contentContainerStyle` (which is an ordinary `View`, with no drawing cache quirk)
and add `minHeight: '100%'` so short content still fills the viewport:

```tsx
// ❌ Don't — native ScrollView drawing cache on Android
<ScrollView style={{ flex: 1, backgroundColor: colors.background }}>

// ✅ Do — plain View inside the ScrollView
<ScrollView
  style={{ flex: 1 }}
  contentContainerStyle={{
    backgroundColor: colors.background,
    minHeight: '100%',
  }}
>
```

The same rule applies to `FlatList` and `SectionList` — use `contentContainerStyle`,
not `style`, for theme-reactive backgrounds.

Note: the library already paints its own root background behind the tree using the
[`backgroundColor`](/docs/api/create-theme-transition#backgroundcolor) config
option, so in many apps you don't need a background on the scroll view at all.

## Error messages reference

| Error | Cause |
|---|---|
| `themes must contain at least one theme` | Empty `themes` object |
| `"system" is a reserved name` | Theme named `'system'` — rename it |
| `different token keys` | Theme keys don't match across themes |
| `systemThemeMap maps to non-existent theme` | Typo in `systemThemeMap` values |
| `initialTheme resolved to non-existent theme` | `'system'` + custom names without `systemThemeMap` |
| `useTheme must be used inside a ThemeTransitionProvider` | Hook called outside provider tree |
