## Upgrading from 1.x to 2.0

2.0 introduces a discriminated-union `SetThemeOptions` with short, per-variant
field names; unifies `origin` / `originRef` into a single `origin`; replaces
`invertedCircularReveal` with an `inverted` flag; and collapses the `useTheme`
overloads into a single signature. Old call sites will fail to typecheck.

### Renamed fields

| 1.x | 2.0 |
|---|---|
| `{ transition: 'wipe', wipeDirection: 'up' }` | `{ transition: 'wipe', direction: 'up' }` |
| `{ transition: 'slide', wipeDirection: 'left' }` | `{ transition: 'slide', direction: 'left' }` |
| `{ transition: 'split', splitAxis: 'vertical' }` | `{ transition: 'split', axis: 'vertical' }` |
| `{ transition: 'pixelize', pixelizeBlockSize: 64 }` | `{ transition: 'pixelize', blockSize: 64 }` |
| `{ transition: 'dissolve', dissolveGrainSize: 8 }` | `{ transition: 'dissolve', grainSize: 8 }` |

### Origin unified

```tsx
// 1.x — two separate fields with manual priority
setTheme('dark', { transition: 'circularReveal', origin: { x, y }, originRef: ref });

// 2.0 — single field, accepts point OR ref
setTheme('dark', { transition: 'circularReveal', origin: { x: 100, y: 200 } });
setTheme('dark', { transition: 'circularReveal', origin: ref });
```

### Inverted reveals

```tsx
// 1.x — separate transition type
setTheme('dark', { transition: 'invertedCircularReveal' });

// 2.0 — flag on the reveal variant
setTheme('dark', { transition: 'circularReveal', inverted: true });
```

The `inverted` flag is also available on `heart` and `star` — the old theme
shrinks into the shape instead of the new theme expanding out of it.

### `useTheme` single signature

```tsx
// 1.x — overloaded, base vs. selection-tracking
const { colors, setTheme } = useTheme();
const { selected, select } = useTheme({ initialSelection: 'system' });

// 2.0 — always returns the full shape
const { colors, setTheme, selected, select } = useTheme();

// `initialSelection` is now an optional seed override
const { selected, select } = useTheme({ initialSelection: 'system' });
```

The `ThemeSelectionResult` type has been removed — `UseThemeResult` now
contains `selected` and `select`.

### New in 2.0

- **Transitions**: `circularReveal`, `wipe`, `slide`, `split`, `heart`, `star`,
  `pixelize`, `dissolve` — 8 new styles on top of the v1 `fade`. Every reveal
  and shape transition also supports an `inverted` flag.
- **`useReducedMotion()` hook**: read the OS Reduce Motion setting in your own UI
- **`TRANSITION_TYPES`** runtime export: the canonical list, handy for pickers
- **Config `animated`**: global opt-out for instant-switching apps
- **Config `backgroundColor`**: function that picks the root background color
  from the current theme, so the Skia snapshot path can't leak the Activity's
  default window color through transparent regions on Android

## From another theme system

The migration follows the same pattern regardless of your current approach:

<Steps>
  <Step>**Install** the library and peer dependencies</Step>
  <Step>**Create the theme file** — define tokens, call `createThemeTransition`</Step>
  <Step>**Wrap with provider** — add `ThemeTransitionProvider` at the root</Step>
  <Step>**Bridge** your existing state to the provider via a bridge component</Step>
  <Step>**Replace** color references from your old system to `useTheme().colors`</Step>
  <Step>**Remove** the old theme context/provider once fully migrated</Step>
</Steps>

## From plain Context / useState

This is the simplest migration — fully replace the old context.

### Before

```tsx
const ThemeContext = createContext({
  theme: 'light', colors: lightColors, toggle: () => {},
});

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const colors = theme === 'light' ? lightColors : darkColors;
  return (
    <ThemeContext.Provider value={{ theme, colors, toggle: () => setTheme(t => t === 'light' ? 'dark' : 'light') }}>
      {children}
    </ThemeContext.Provider>
  );
}
```

### After

```ts title="src/lib/theme.ts"
import { createThemeTransition } from 'react-native-theme-transition';

export const { ThemeTransitionProvider, useTheme } = createThemeTransition({
  themes: { light: lightColors, dark: darkColors },
});
```

```tsx
// Before:
const { colors, toggle } = useContext(ThemeContext);

// After:
const { colors, name, setTheme } = useTheme();
const toggle = () => setTheme(name === 'light' ? 'dark' : 'light');
```

## From React Navigation theming only

If your only theme system is `NavigationContainer`'s `theme` prop:

```ts title="src/lib/theme.ts"
const light = {
  primary: '#007AFF', background: '#ffffff', card: '#ffffff',
  text: '#000000', border: '#d8d8d8', notification: '#ff3b30',
};

const dark: Record<keyof typeof light, string> = {
  primary: '#0A84FF', background: '#000000', card: '#1c1c1e',
  text: '#ffffff', border: '#333333', notification: '#ff453a',
};

export const { ThemeTransitionProvider, useTheme } = createThemeTransition({
  themes: { light, dark },
});
```

Bridge to NavigationContainer:

<Callout type="info">
  This example uses `name === 'dark'` for simplicity. If your app has custom
  dark-ish themes, define a set and check membership instead:
  `const DARK_THEMES = new Set(['dark', 'midnight']); dark: DARK_THEMES.has(name)`.
</Callout>

```tsx
function AppWithNavigation() {
  const { colors, name } = useTheme();

  return (
    <NavigationContainer theme={{
      dark: name === 'dark',
      colors: {
        primary: colors.primary, background: colors.background,
        card: colors.card, text: colors.text,
        border: colors.border, notification: colors.notification,
      },
    }}>
      <AppNavigator />
    </NavigationContainer>
  );
}

// Root:
<ThemeTransitionProvider initialTheme="system">
  <AppWithNavigation />
</ThemeTransitionProvider>
```

## Preserving an existing useTheme hook

If your codebase already has a `useTheme` hook with a different return shape:

<Callout type="info">
  The adapter below maps `isDark` from `name === 'dark'` because the migration
  example assumes `light` and `dark`. For custom theme names, replace that check
  with your own dark-theme set.
</Callout>

```ts title="src/lib/theme.ts"
const api = createThemeTransition({ themes: { light, dark } });

export const ThemeTransitionProvider = api.ThemeTransitionProvider;

// Adapter: match your old hook's return shape
export function useTheme() {
  const { colors, name, setTheme, isTransitioning } = api.useTheme();
  return {
    colors,
    theme: name,         // your old code used 'theme' not 'name'
    isDark: name === 'dark',
    toggle: () => setTheme(name === 'light' ? 'dark' : 'light'),
    setTheme,
    isTransitioning,
  };
}
```

This lets you migrate incrementally — old components keep working while you
update them one by one.

## Migration checklist

- [ ] Install library and peer dependencies
- [ ] Create theme file with matching token keys across all themes
- [ ] Wrap root with `ThemeTransitionProvider`
- [ ] (Optional) Create adapter hook for incremental migration
- [ ] Replace color references from old system to `useTheme().colors`
- [ ] Replace theme toggle logic with `setTheme()` or `select()`
- [ ] Remove old context/provider
- [ ] Test: light↔dark, system mode, rapid taps, background/foreground
