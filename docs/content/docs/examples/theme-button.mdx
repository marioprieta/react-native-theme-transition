title: Theme Button
description: Simple cycling button that uses setTheme directly — no selection tracking needed.
---

A button that cycles through themes. Since the button's visual appearance doesn't change
on theme switch (it just shows a static label), no selection tracking is needed.

```tsx
import { Text, Pressable } from 'react-native';
import { useTheme } from '@/lib/theme';

const CYCLE = ['light', 'dark'] as const;

export function ThemeButton() {
  const { colors, name, setTheme, isTransitioning } = useTheme();
  const nextIndex = (CYCLE.indexOf(name as typeof CYCLE[number]) + 1) % CYCLE.length;

  return (
    <Pressable
      onPress={() => setTheme(CYCLE[nextIndex])}
      disabled={isTransitioning}
      style={{
        padding: 16,
        borderRadius: 12,
        alignItems: 'center',
        backgroundColor: colors.primary,
      }}
    >
      <Text style={{ color: '#fff', fontSize: 16, fontWeight: '600' }}>
        Switch theme
      </Text>
    </Pressable>
  );
}
```

<Callout type="warn">
  **Do not change styles based on `isTransitioning`** (e.g., `opacity: isTransitioning ? 0.5 : 1`).
  The screenshot captures the current visual state — if the button is dimmed when the screenshot
  is taken, the cross-fade will blend the dimmed state with the new theme, producing a visible flash.
</Callout>

## When to use `setTheme` vs `select`

Call `setTheme` directly when the trigger has **no visual state that must
match the screenshot** — a plain "Switch theme" button, a programmatic change
from an effect, a deep link, a settings screen. `setTheme` is also the right
call for any non-UI trigger (analytics, persistence, haptics).

Use `select()` whenever a highlight, toggle thumb, pill, or checkmark reflects
the chosen theme — it defers `setTheme` by one animation frame so the pressed
state is painted before the screenshot is captured. See
[Theme Picker](/docs/examples/theme-picker) for that pattern.
