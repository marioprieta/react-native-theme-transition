`react-native-theme-transition` ships as a pure JavaScript / TypeScript
package. Installing it means installing the package itself plus the
peer dependencies that handle the heavy lifting: `@shopify/react-native-skia`
(snapshot capture and rendering), `react-native-reanimated` (the
animation driver), and `react-native-worklets` (the worklet runtime
Reanimated 4 builds on).

## Installation

<Callout type="info">
  **Runtime baseline: Expo SDK 58.** Current device checks use native Debug
  builds of the demo app on Expo 58.0.25 with React Native 0.88.1, an iOS 26.5
  simulator and an Android API 37 emulator. Earlier checks used Expo Go 58.0.3
  with React Native 0.88.0. Install native peers with `npx expo install` so
  their JavaScript versions match your SDK's native runtime. The declared peer
  ranges do not prove compatibility with every older Expo Go release.
</Callout>

SDK 54 already bundles Skia 2.2.12, Reanimated ~4.1.1 and Worklets 0.5.1
([Expo's SDK 54 manifest](https://github.com/expo/expo/blob/sdk-54/packages/expo/bundledNativeModules.json)).
Its exclusion cannot be justified by missing Skia 2 or Reanimated 4 bindings;
the current engine still needs an SDK-specific compatibility check before
claiming support on that runtime.

<Tabs items={['Expo', 'React Native CLI']}>
  <Tab value="Expo">
    Install every native peer explicitly, using the versions matched
    to your Expo SDK:

    ```bash
    npx expo install react-native-theme-transition @shopify/react-native-skia react-native-reanimated react-native-worklets
    ```

    No additional Babel configuration is needed for this Expo setup:
    `babel-preset-expo` already registers the worklets plugin.
  </Tab>
  <Tab value="React Native CLI">
    ```bash
    npm install react-native-theme-transition @shopify/react-native-skia react-native-reanimated react-native-worklets
    ```

    Then install the iOS pods:

    ```bash
    cd ios && pod install && cd ..
    ```
  </Tab>
</Tabs>

## Tested Versions

The peer ranges in `package.json` are declared requirements, not a
guarantee that their minimum versions work together. Each peer also has
its own compatibility constraints. Development and configured CI checks
use a tighter set:

| Peer | Declared minimum | Tested against |
|---|---|---|
| `react` | `>=19.0.0` | `19.3.0` |
| `react-native` | `>=0.78.0` | `0.88.1` |
| `@shopify/react-native-skia` | `>=2.0.0` | `2.14.x` (test suite and build); `2.4.18`, `2.6.2`, and `2.14.0` (type-check and build) |
| `react-native-reanimated` | `>=4.0.0` | `4.7.x` |
| `react-native-worklets` | `>=0.5.0` | `0.13.x` |

"Tested against" distinguishes the configured CI checks from runtime checks. The unit
suite and lint run on the locked SDK 58 development baseline (Expo 58.0.25,
React Native 0.88.1, `@shopify/react-native-skia` 2.14.0, the version Expo SDK 58
installs). CI is configured to run the type-check and build against exactly Skia
2.4.18, 2.6.2, and 2.14.0. The minimum peer ranges are broader than
this matrix, so versions between those points are not
exercised; the alternate Skia versions in the matrix are types/build
only and never run on a device.

Device checks use native Debug builds of the demo app on Expo 58.0.25 with
React Native 0.88.1 (iOS 26.5 simulator and Android API 37 emulator). Each
platform ran all nine transitions light→dark and dark→light (18/18), including
the inverted heart and star transitions on Skia 2.14.0. Earlier checks used
Expo Go 58.0.3 with React Native 0.88.0. These are simulator/emulator results:
no physical-device, 120 Hz, or universal flash-free guarantee is claimed.

If you hit a real bug on the declared minimums, please file an
issue with your exact lockfile versions.

## Bare React Native CLI: Verify the New Architecture

Reanimated 4 requires React Native's New Architecture
(Fabric + TurboModules). The RN 0.88 development baseline uses it.
Enabling Fabric alone does not prove that every version combination
in the declared peer ranges is compatible.

Bare React Native CLI projects upgraded from older versions can
still have the old architecture wired in. Confirm before installing:

- **iOS**: `ios/Podfile` should not pin `:fabric_enabled => false`.
- **Android**: `android/gradle.properties` should have `newArchEnabled=true`.

If either is off, enable it and run a clean install (`pod install`,
Gradle sync). Without the New Architecture the build fails with
errors that mention `RCTFabric` or `TurboModule`.

## Configure Babel (Bare React Native CLI)

Expo apps using the documented preset setup skip this section: `babel-preset-expo` already
registers the worklets plugin (and Reanimated's plugin).

Bare React Native CLI projects must add `react-native-worklets/plugin`
as the **last** plugin in `babel.config.js`:

```js title="babel.config.js"
module.exports = function (api) {
  api.cache(true)
  return {
    presets: ['module:@react-native/babel-preset'],
    plugins: [
      // Do NOT add 'react-native-reanimated/plugin' — the worklets
      // plugin replaces it.
      'react-native-worklets/plugin', // must be last
    ],
  }
}
```

## Clear Cache and Restart

```bash
npx expo start -c
```

## Verify The Install

The fastest way to confirm the install is healthy: open
`src/lib/theme.ts` in a fresh file and import the factory. If
TypeScript autocompletes the `createThemeTransition` symbol and the
Metro log shows no warnings about missing native modules, the
install is good.

```ts title="lib/theme.ts"
import { createThemeTransition } from 'react-native-theme-transition'

export const { ThemeTransitionProvider, useTheme } = createThemeTransition({
  themes: {
    light: { background: '#ffffff', text: '#000000' },
    dark: { background: '#000000', text: '#ffffff' },
  },
})
```

If Metro complains about `@shopify/react-native-skia` or
`react-native-worklets`, see [Troubleshooting](/docs/guides/troubleshooting).
The most common cause is forgetting to clear the Metro cache after
adding the worklets babel plugin.
